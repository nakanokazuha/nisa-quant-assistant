# Phase 3 model and evaluation

Phase 3 is implemented as a small, deterministic, supervised cross-sectional ranking workflow. It does not use an LLM for numeric prediction and it has no order or broker execution path.

## Model

- The transparent factor baseline combines 1/3/6/12-month momentum, benchmark-relative strength, volatility, and drawdown.
- The specialized baseline is a deterministic standardized diagonal ridge-like fit over a small tabular feature schema. It is not a true multivariate ridge solve: each standardized feature receives an independent regularized covariance coefficient. Its numeric prediction is the forward three-month excess return versus the selected S&P 500 benchmark proxy; predictions are ranked cross-sectionally each monthly decision date. This 3-month target is a model-training and prediction-ranking target, not the return compounded for a monthly portfolio.
- A current prediction `score` is model output for descriptive research ranking. It is not a recommendation, not a calibrated probability, and not evidence of future outperformance. Current-only rows use the surviving current universe and are therefore survivorship-limited.
- LightGBM and scikit-learn are intentionally not required by this checkout: neither is available in the minimal current environment, and the dependency-free ridge model is small, inspectable, deterministic, and sufficient for pipeline verification. Replacing it with LightGBM is a future model change, not an implicit runtime fallback.
- Model artifacts include versioned exact bindings: content-derived model identity/hash, feature schema, exclusive training cutoff/window, target horizon, benchmark, return basis, dataset/history identities, coefficients, intercept, normalization means/scales, residual standard deviation, training row count, and the missing-feature policy plus its training-derived imputation values. Loaders reject unknown/missing fields, non-finite values, and tampered content.

## Features and leakage controls

The monthly panel uses only bars at or before each decision date and SEC facts whose `filed_at` is at or before the decision cutoff. Features include momentum, annualized rolling volatility, drawdown, relative strength, dollar-volume/liquidity, volume trend, latest available revenue, revenue growth, net margin, filing/event counts, missingness, and staleness. Features and labels use the `price_return` basis for both assets and the `^GSPC` price-index benchmark; a total-return window is rejected unless both sides provide adjusted-close observations. Targets are never used to build same-date features. `target_1m_*` uses the next monthly decision date as a disjoint interval; `target_3m_*`, `target_6m_*`, and `target_12m_*` use 90, 180, and 365 calendar-day endpoints and record whether those endpoints are observable. Rows missing a complete future horizon are retained for panel inspection but excluded from the relevant supervised or realized-return calculation.

The default model target is `target_3m_excess_return`. The monthly backtest realization and benchmark compounding use `target_1m_return` and `target_1m_benchmark_return` on the explicit `price_return` basis; `target_1m_excess_return` is retained in rows but is not used for a separately reported hit-rate metric. No rank-IC, probability-of-profit, or alpha metric is calculated or emitted.

## Walk-forward evaluation

The evaluator trains on dates before a validation window, then tests the next locked monthly date. It records each requested top-k portfolio's selected count, price return, and turnover, the factor-baseline selection and price return, the benchmark price return, cumulative top-k and benchmark returns, top-k benchmark-relative returns, transaction costs, return bases, and the explicit interval convention. It does not currently calculate annualized return, drawdown, volatility, hit rate, rank IC, validation error, or abstention statistics; those remain future extensions.

Each test-date observation is a non-overlapping one-month forward price-return observation at a monthly decision cadence. Training rows are purged when the selected target horizon's forward endpoint falls after the validation start; this embargo prevents a label that was not yet observable from entering the fit. The default target horizon remains 3 months, with 6-month and 12-month fits using their own endpoint observability. The default transaction-cost assumption is 10 basis points applied to monthly turnover, where turnover is the symmetric difference between prior and current holdings divided by the current selected count. The 3-month prediction/rank target remains visible as evaluation metadata but is never compounded as a monthly portfolio return. The current reference universe is not historical membership; its backtest is descriptive survivor-selected evidence and suppresses benchmark-relative/performance claims until point-in-time membership is integrated.

## Scenarios and confidence

Missing numeric features are imputed only after labels have been selected: each feature uses the mean of its finite observed training values, with deterministic `0.0` only when that feature has no observed training value. The policy is applied with the stored training statistics at prediction time. Missingness and staleness remain explicit feature columns; missing SEC facts are never converted into issuer values. Target labels are never imputed, and all training rows remain subject to the exclusive cutoff and target observability rules.

Base, bull, and bear bounds are deterministic uncertainty heuristics: the prediction plus/minus 1.5 residual standard deviations. They are not calibrated probabilities and are never called calibrated. Confidence describes evidence and model quality (`high`, `medium`, or `low`), and low evidence always caps confidence at `low`. Missing/non-finite features that cannot be represented as missing produce abstention with no numeric scenario. Zero training rows, zero validation periods, or zero eligible selections produces `performance_claims_unavailable=true`.

Backtest artifacts use a closed metrics schema. The calculated fields are the benchmark/top-k cumulative and benchmark-relative returns, transaction cost, turnover/return/interval conventions, evidence and availability statuses, and boolean suppression flags; `insufficient_data_reason` is present only for `unavailable_insufficient_data`. Each metric number is a finite non-boolean number or `null` when the calculated observation is suppressed or unavailable. Periods contain only the decision date, benchmark return, factor-baseline selection/return/turnover fields, turnover convention, and the matching `top_<k>_selected`, `top_<k>_return`, and `top_<k>_turnover` fields. Unknown fields such as alpha or annualized return are rejected even when an artifact hash is recomputed.
