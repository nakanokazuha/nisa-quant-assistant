# NISA Phase 2 Evidence Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a read-only, provider-neutral US S&P 500 evidence refresh layer that is reproducible, provenance-safe, idempotent, and incapable of emitting Phase 3 verdicts or trade actions.

**Architecture:** Keep the existing local SQLite ledger and deterministic core unchanged for compatibility. Add Phase 2 tables to the existing initializer, typed adapters/orchestration in `evidence_providers.py` and `evidence_collection.py`, and isolated CLI commands for fixture refresh and evidence inspection. Reuse UTC parsing and fail-closed numeric principles while storing OHLCV, filings, news, and alerts in dedicated tables.

**Tech Stack:** Python 3.11 standard library, SQLite, `csv`, `json`, `urllib`, `xml.etree.ElementTree`, and `unittest`; no new dependency.

**Spec:** `docs/specifications/phase2/2026-09-01-nisa-phase2-r1-design.md`, `docs/specification.md`, and the task contract.

## Global Constraints

- Universe: US-listed S&P 500 constituent equities only; every snapshot records identifier, effective date, source, retrieval time, look-ahead status, and survivorship-bias status.
- Phase 2 output is evidence/context only; no predictions, research synthesis, BUY/HOLD/SELL verdicts, order payloads, broker capability, or automatic trading.
- Network is read-only, HTTPS-only, host-allowlisted, timeout-controlled, no-redirect, and injectable; credentials are caller configuration and never persisted or logged.
- Every accepted record has typed identity, UTC retrieval time, observation/publication/period dates where applicable, citation, source version, finite values, chronology, freshness, and conflict status.
- Existing fixture/CSV/SQLite/CLI behavior remains compatible; no `yume-ios` files are touched and no push is performed.
